# 3090 结果：Found 损失诊断与修复顺序

日期：2026-09-28。此文是导入结果分析及有界机制检查，不是新的正式性能评价。

已确认两条需要优先修复的机制：**连续位置与图端点快照失配，加上失败重试和冷却的配合问题；路径段安全检查漏掉占据体素边界，执行期间又未及时复核。** 旧日志足以量化碰撞和超时造成的 Found 损失，但不足以给这些机制分配全体回合的因果占比。

## 2. 超时机制：当前位置没有图连接，失败重试反复保留旧分配

在 B0 验证场景 `unknown_validation_m20_0029` 的前 100 步，记录了原查询的真实返回原因，未额外调用规划查询：

- 搜索候选查询成功 36 次，失败 **15,181 次，全部为 `no_start_connector`**；不含初始化查询。
- 首次失败在第 63 步。此时智能体位置已更新，但规划图中没有对应当前位置的端点。该错误发生在检查图连通分量之前，不能解释成物理地图不可达。
- 第 63、68、73、78、83、88、93、98 步共 8 次原子重分配失败，分配哈希每次均保持不变。
- 第 60 步完整刷新时查询仍可达，但提案因相对收益不足被拒绝。第 80、100 步再次完整刷新，却被 `REJECT_EVENT_COOLDOWN` 拦截；等到允许重试，智能体又已移动，端点再次失配。
- 100 步中有 16 步至少一个搜索者满足运动停滞代理条件，合计 34 个搜索者·步。执行者待命造成的低位移不计入该数。

源码解释与记录一致：`state_provider.snapshot()` 的增量分支更新 agent 位置，沿用旧 planning_graph；`TravelCostService.query()` 在当前起点没有连接时直接失败；控制器失败后仍保留旧分配。额外合成测试在空的连通图中仅移动起点 0.013，就复现相同错误；给这个合法短线段补上端点后恢复可达。

历史 B0 的 23 个未发现超时回合累计 2,204,545 次搜索不可达查询、1,248 次缺路导致的部分分配拒绝。旧计数未保存具体原因，上述 15,181 次的归因只针对本次短探针，不能直接扩展到全部历史查询。

证据：[场景 29 机制汇总](b0_scene29_mechanism_summary.json)。

## 3. 碰撞机制：名义路径已不安全，不能仅归因于惯性偏航

B0 验证场景 `unknown_validation_m20_0004` 在第 18 步发生搜索者 0 与障碍 0 碰撞。短探针与原导出的终止步、碰撞双方完全一致，导出的碰撞坐标最大差为 **0.0**。

- 碰撞前速度约 1.959，活动路径段横向偏差仅约 0.075。此前速度从第 12 步约 0.944 持续增大。
- 原名义路径段 `[3,9,2.5] → [1,7,1.5]` 本身穿过真实障碍。真实障碍仅在事后审计中使用，从未进入控制输入。
- 更关键的是，仅利用**初始公开占据图**，该线段就在 `[2,8,2]` 接触已占据体素 113 的闭边界；加上配置中的 0.4 clearance 后仍相交。这不是必须知道隐藏真值才能发现的风险。
- 所用公开图规划器的 `_segment_is_free_np()` 丢弃 clearance 参数，只检查沿线采样点对应的体素；这种检查会漏掉体素边界接触。配置了 clearance 不代表这条调用路径实际应用了它。
- 控制器从初始分配一直使用到碰撞，持有 map revision 1，最新公开图已到 revision 18；期间是 `NO_REPLAN_EVENT`，20 步周期刷新尚未到达。

碰撞点对应体素在记录中先为 known_free，最后变成 unknown，未被标为 occupied。因此不能把此例写成“已经明确发现碰撞障碍，却故意不刹车”，也不能从这些日志得出精确首次感知到减速的延迟。证据支持的是：粗栅格和采样线段检查留下风险，当前执行链缺少及时的保守路径复核。

证据：[场景 4 几何及终止事件核对](b0_scene4_geometric_trace_summary.json)。

## 4. 对症修复的具体顺序

冻结 B0/Phase 1B 行为保持原样。以下变更应作为 Chapter 3 的独立、显式启用方案，先进行同场景短前缀消融；不改奖励、观测、动作维度、严格碰撞终止条件或障碍真值。

| 顺序 | 实现内容 | 短测试验收 |
|---|---|---|
| P1 端点一致性 | 每次分配前用当前位置建立经过公开图碰撞检查的临时起点连接；区分端点缺失、非法端点和图分量不连通；同一步修复起点后最多重试一次，避免按候选重复查询同一坏起点。 | 场景 29 的端点失配失败显著消失；真正无连接的夹困场景仍失败；禁止用未校验的近邻吸附穿墙。 |
| P1 失败与冷却 | 将地图/端点版本变化纳入失败缓存失效条件；完整刷新应允许处理尚未解决的路径失效。区分成功重规划冷却与失败退避。失效安全事件不受收益门槛约束。 | 第 80/100 步的有效刷新机会不再被旧失败冷却吞掉；固定坏起点不会产生上千次等价查询。 |
| P1 路径有效性 | 采用闭线段与保守占据体素的连续交集或 supercover 检查，明确应用安全余量；用最新公开图复核当前制动距离内的路径段。候选失败时，旧路线只有仍通过安全检查才可继续，否则进入制动/安全待命。 | 场景 4 初始危险段被拒绝；轴对齐、对角线、面/棱/角接触、窄通道均有几何用例；已知安全路径保持可用。 |
| P2 速度约束 | 在上述检查上增加转弯和可用可见距离约束，速度上限取原上限、转弯约束和制动距离约束的最小值。减速度从现有动力学标定，不能假设一步停住。 | 分别记录路径危险先验、制动触发步、速度、横向偏差；验证碰撞率下降时搜索停滞没有恶化。 |
| P3 待命行为 | 单独检查执行者待命移动的路径、速度与必要性，再做安全待命消融。 | 保留它引起的发现前碰撞单独统计，不用执行者正常静止抬高搜索停滞率。 |

这些是依据本次证据收敛后的修复工作项，尚未作为生产算法启用，也未宣称 Found 已提升。先分别验证端点修复和路径安全，再验证组合；此时只做有界探针，不自动开启长训练或恢复模型。
