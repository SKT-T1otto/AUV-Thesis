## B. 代码工作包

以下为拟新增模块名，不表示文件已经存在。

| 模块 | 首版实现 | 验收 |
|---|---|---|
| `public_geometry.py` | 公开占据体素的闭线段-AABB/supercover 相交检查；显式 clearance；用于连接段、图边、平滑后路径和实际当前位置到跟踪点。仅使用公开占据图。 | 面/棱/角接触均不漏检；越界、零长线段、非法起点、窄通道测试齐全；场景 4 的危险段必须被拒绝。 |
| `planning_refresh.py` | 在一次实际分配/重分配前预检所有参与智能体的当前起点。若当前坐标缺少端点，完整刷新一次公开规划快照，并让候选生成、评分、控制器及 guidance 使用同一份快照；同一步只刷新一次、最多重试一次。 | 场景 29 不再用缺失端点枚举数千候选；真实无可用连接仍返回失败；不使用未经检查的近邻吸附。 |
| `failure_policy.py` | 分开记录成功冷却与失败退避。失败按 agent、起点、相关地图版本和阶段缓存；同一失败状态直接复用原因。目标达成/旧路线失效形成未解决任务，新有效快照可立即处理；普通收益型优化仍遵守原冷却。 | 复现第 80/100 步刷新被旧失败冷却阻断的用例并消除；重复起点失败查询每次分配最多一次；不会因无关 map revision 改变而反复重算。 |
| `safe_guidance.py` | 初始路线安装前、每次新路线安装前，以及每个搜索步动作执行前检查路线。路径无效时优先重规划；无安全替代路线则更新跟踪点，使原先验控制器制动。使用独立安全状态与恢复条件。 | 不再执行已知无效旧路线；不修改语义搜索目标来伪造目标到达；制动保持有限加速度，不能直接清零速度或位置。 |
| `runtime.py` / `run_paired.py` | 装配上述模块、运行 V0–V4、复用已有诊断；先支持 B0，再接 B1。所有物理步仍走唯一 core 环境。 | 全关闭逐步等价；计时、发现、碰撞、交接顺序不变；输出新目录且原数据只读。 |

`planning_refresh` 首版选择完整快照刷新，是为了直接验证失配机制。它也更新公开地图和 belief，所以 V1 的效应必须解释为“规划状态一致性修复”，不能声称是严格隔离的端点插值效应。只有正确性和收益得到确认后，再优化为基于同一地图的端点增量更新，并另做等价核验。

安全图应基于原图过滤危险节点/边，沿用原安全边的成本及原路径查询算法；过滤后重算连接/连通标签和图身份，避免借用旧标签制造虚假可达。只在最终路径上反复拒绝同一危险路径不足以完成修复。clearance 初值从场景已有配置读取，本批次为 0.4；首轮不搜索最优余量。unknown 不直接等同 occupied，仍单列未知风险。

安全模块必须在**初始化首次安装 guidance 前**介入，不能先调用旧 runtime 完成危险初始分配再事后替换。优先新增窄的装配工厂/策略注入点；若无法在独立入口完成，必要的共享调用链变更也须单独记录来源演进并回归冻结行为。

首版制动通过缩短沿安全方向的跟踪距离，或将跟踪点设为当前位置，使现有速度先验产生减速。不能认为设置 hold 就能瞬间停下。需按现有 drag、flow、速度/加速度上限标定制动距离，覆盖横向/纵向运动和流场扰动。若制动可行域不存在，记录 `NO_VERIFIED_SAFE_COMMAND`，不能宣称保证安全。所有附加干预只发生在发现前；发现后清理附加安全状态，继续原执行流程。

完成这轮后再单独加入转弯限速与未知区域速度约束。先不把速度超参数搜索、执行者待命修改和搜索目标评分改动混入本轮。

## C. 五个实验臂

这里的 V 编号是同一 B0 方法的修复变体，不是新的 B0/B1/B2/B3 方法编号。

| 变体 | 规划状态一致性 | 失败与冷却修复 | 路径安全/失效制动 | 要回答的问题 |
|---|---|---|---|---|
| V0 | 关 | 关 | 关 | 原基线 |
| V1 | 开 | 关 | 关 | 起点与公开快照一致后，查询失败是否减少？ |
| V2 | 开 | 开 | 关 | 失败恢复是否进一步减少旧分配和停滞？ |
| V3 | 关 | 关 | 开 | 安全路径检查是否减少早期碰撞，又是否造成等待？ |
| V4 | 开 | 开 | 开 | 两类修复组合后是否持续搜索并提高 Found？ |

V3 的安全路线尝试使用其当前可用的规划快照，不暗中调用 V1 的强制刷新或 V2 的冷却豁免。它需要的每步最新占据图只进入安全检查；取图若产生带新端点的规划快照，不得偷偷传给分配器。无安全替代路线则按定义制动，等待原有合法刷新。V2 没有安全模块时，不能声称处理了旧路线的几何危险。

## E. 指标和日志

- 每回合：Found、发现前碰撞（搜索者/执行者分列）、未发现超时、成功；Found 时间只作为条件分布，不能排除未发现回合后给出总体速度结论。
- 每个搜索步：实际位置/速度、当前路径和段、横向偏差、最新图与规划图版本、当前端点存在性、重试/冷却原因、安全状态、制动开始/结束、语义目标和跟踪点。
- 查询失败：按原因、调用者、起点、地图版本、智能体计数；同时报告查询数/搜索步、修复尝试成功率、保留失效分配时长，不把总查询数当不可达率。
- 停滞：沿用已测试的 10 步窗口，路径进展与净位移阈值均为 0.1，只统计搜索者；同时报告总量/搜索暴露步和最长连续停滞。安全制动、待命、转弯分别列出，不能靠改标签隐藏等待成本。
- 有效搜索：新增实际目标观测更新足迹的只读采集，记录新覆盖格、重复覆盖格、距上次目标观测的年龄；观测足迹来自实际感知/信念更新，不使用真实目标位置或障碍探测覆盖代替。可预定义“新覆盖或间隔至少 30 步的再次观测”对应的有效观测步代理，30 来自现有 revisit half-life；静止的合法再次观测允许计入。它不是精确发现概率，必须与 Found、停滞同时报告；采集未完成前保持 null。
- 计算代价：每物理步墙钟时间、规划次数、完整图刷新次数、查询数，记录相同机器/线程数；不能以十倍计算换来的步数收益冒充同等计算效率。

D3 采用逐场景配对差：Found 增减表、碰撞增减表；按场景做配对 bootstrap 95% 区间（固定统计 seed，10,000 次），二元结果同时报告 discordant pairs。若区间跨 0，写成证据尚不足；不拿开发集显著性支撑最终结论。程序异常/计算预算中止单列，不能删除失败场景来提高 Found。

## F. 何时进入 B2/B3/HGR 与重新训练

只有 D3/D4 通过后，才规划固定 checkpoint 的迁移评价。现有 checkpoint 带源码身份约束，不能直接在改动源码上调用恢复入口：需独立、显式的纯推理兼容路径，验证方法、配置、维度与参数映射，分别记录训练源码、checkpoint hash、评价源码；旧来源检查继续有效，不伪造同源恢复。本轮不加载 checkpoint。

若只是验证修复的即时收益，先冻结权重比较同一验证集。若正式论文要评价“在新安全执行机制下训练的学习方法”，再用相同预算/训练 seed 重新训练 B2/B3/HGR，并在新的未参与调参的测试集评价。不能将当前训练主轨迹的 Found 与修复后的固定 checkpoint 验证 Found 直接作提升幅度比较。
