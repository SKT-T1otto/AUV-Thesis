# BSER D0–D3 完成结果与保留决策

结论：本轮不支持完整联合 BSER（D3）改善发现前搜索表现；最值得继续的是 D2 的“搜索优先、待命顺序优化”。响应加权改变搜索路线并未带来总体收益，增加了失败风险。当前不能据此写成“完整 BSER 已证明有效”，也没有必要立即丢弃整个响应/待命方向。

## 核验范围

20 个固定开发场景，4 组，共80个真实终止回合、23,647物理步；耗时8,886.21秒，约2小时28分钟。逐个复核子任务 identity/result 与总表一致、完整终止、连续 trace/trace哈希、planning audit哈希、场景及种子、零残差和无训练。当前来源/输入与运行封存一致，重新汇总与原 summary 一致，并独立从80条结果复算三个主指标。5份旧参考证据哈希未变。

这是共同 V4、重评分和事件接受协议下的新实验，不是历史 B0/B1 的原样复跑。样本只有20个重复使用开发场景，80回合不是80个独立样本。检查过程不重跑环境、不修改运行结果或算法。

D2相对D0少碰撞的配对为7场，新增加碰撞为1场；Found新增在原始索引3、10、46、91，丢失63、86。7场避免碰撞中，3场变成Found，4场变成未Found超时。因此延长安全搜索寿命确有用，但安全存活不是充分条件。

D3相对D2丢失的Found为3、10、46、91、95。新增碰撞为3、46、62、78、91、95，没有任何场景反向减少碰撞；其中5场由搜索者碰撞，只有78由执行者待命运动碰撞，不能把主要退化归结为“执行者乱动”。

小样本不确定性：D2−D0 Found差的配对bootstrap 95%区间为[−15,+35]个百分点，exact McNemar双侧p=0.6875；碰撞差区间[−55,−5]个百分点，但exact p=0.0703125。D3−D2 Found exact p=0.0625；碰撞exact p=0.03125，属于未作多重比较校正的次比较。bootstrap区间与离散精确检验可不同，不能挑有利口径写“显著证明”。目前是明确的开发取舍信号，不是确认性统计证明。

## 为什么目前的联合机制没有收益

### 响应加权已生效，而不是模块没运行

D1有112/335条提案改变同状态纯搜索选择（33.43%），D3有44/273条（16.12%）；各涉及17个场景。D3至少33条改变提案可匹配同一步已接受且搜索ID相同的决策。原评分保留问题的修正也实际触发：D0/D1/D2/D3在稳定处理后重评分发生变化的次数分别25/43/32/32。因此不能简单归因为开关没打开或旧分数完全覆盖了新逻辑。

模型定义是信念质量×规划路径探测概率×从待命点出发的指数响应权重。它偏好更易响应的探测区域，但没有直接优化实际发现时间，也没有在这个评分里显式计入路径跟踪可执行性、转弯惯性、Hold后的安全状态、执行者移到待命点所需时序。全规划路线的覆盖也不等于下一段能真正执行的覆盖。这些是已核实的模型边界；哪一项贡献最大尚需单因素验证。

实例：场景3在第20步，D3为联合代理分数从0.410380升到0.410999（约+0.151%）改变了搜索选择；D2于144步Found，D3于254步搜索者0碰撞且未Found。该场景支持“小的代理收益伴随较差实际结果”，但不能证明这一次换路独自造成全部后续退化。D3所有提案的联合分数相对同池纯搜索后顺序待命平均增量仅0.0003203；还有7条低于顺序方案，反映贪心近似并不保证支配另一启发式。

### 路径失效后的物理安全仍是直接失败环节

碰撞前一物理步已处于Hold且不可达的次数：D0 8/9、D1 8/9、D2 3/3、D3 7/9，合计26/30。Hold没有等同于物理停止。D3场景95碰撞前已Hold，速度仍约1.56；场景62已Hold，速度约1.30。D3场景3则仍在搜索跟踪，横向偏差约1.83。日志确认的是碰撞前状态；惯性、流场、制动时机的相对贡献还未通过反事实实验分开。

故当前既有高层目标与Found不一致的问题，也有底层安全问题。只改BSER评分不能保证安全，且不宜重新直接启用此前造成跟踪停滞的R2/R4整套修复。

### D2的收益不能全部命名为“响应最优性收益”

D0与D2的20个初始搜索状态和分配全部一致；之后17场搜索者运动发生分歧，这17场均先观察到公开规划地图差异。core/env/uav_env.py 的 `_sense_and_update_shared_map` 对全部4个智能体进行障碍扫描并共享地图，执行者移动会改变搜索者随后获得的地图。

因此D2待命策略的总效果包括迁移位置、响应位置、共享探图以及随后的事件/路径变化。当前设计可以评估这一总效果，却没有隔离“优化响应位置”相对于“一般有用移动”的增量。需要增加移动但不使用BSER响应目标的对照，如公开安全路径到搜索者质心/公共几何中心；保持原感知与任务协议，不能直接把全队感知改掉当同一个任务。

D2相对D0的停滞+保持占比从12.65%降至8.26%，有效观测步占比从41.31%升至43.69%。D3为8.77%、43.47%，与D2接近却碰撞更多，因此“普通覆盖占比”不足以解释两者的成功率差。

## 响应阶段的线索

D2与D0共同Found的8场，Found时执行者距目标平均少3.09距离单位；D3与D0共同Found的7场少2.68。D3与D2共同Found的7场只再少0.19，handoff距离差只约−0.21。待命优化有响应位置收益线索，联合搜索的额外响应收益很小。上述均为结果筛选后的共同可观测子集，不能推广为总体因果效应。

完整成功为D0/D1/D2/D3=1/2/4/3，仅作次指标记录，当前不以此确定算法优劣或宣布执行阶段优化通过。

## 建议与论文取舍

1. 将D2作为下一轮工作基线，保留D0作对照。暂停把现有D3作为推荐方案；现在不能写完整BSER已提高Found。
2. 最优先补一个“安全移动但无响应优化”的待命对照，并在未用于当前调参的独立场景中配对确认D0、D2和该对照。判断D2是否优于普通移动，而不仅优于原地等待。
3. 对联合机制若再做一轮修正，应明确限定为搜索优先：先保留近似最优纯探测候选，只在其内用响应作次级选择，并设置可执行性/迁移代价约束。不要继续无限调tau寻找正结果；小代理收益不得无条件触发换路。是否有用仍需D2配对验证。
4. Hold安全先做局部短程场景验证：检查何时进入Hold、剩余速度和障碍距离、制动是否保持进展；通过后统一施加到所有对照组。不要将高层BSER修改与底层安全修改只加在实验组上。
5. D2仍有5场未Found超时、3场发现前碰撞。除了局部安全修复，后续需要审计搜索覆盖/重复路线/失效恢复，不能仅增加执行者运动。

建议保留“搜索—响应协调”研究方向，收缩并重构现有联合目标。若独立确认表明D2不优于普通安全移动，或改良联合方法不能超过D2，则应放弃“联合响应加权能改善搜索”的核心主张；不能仅将D2换名就视为原BSER创新点验证成功。具体论文创新性还需与相关方法界定，本轮实验本身不证明新颖性。
