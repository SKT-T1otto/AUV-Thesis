# D2 第二轮优化：机器漂移复测

2026-10-10；最新记录的本地验证，不是 CI 或正式实验验收。

这次固定性能核、相同启动方式、交错顺序的重复测量，得到**完整 rollout 吞吐提升 11.03%，有界真实训练吞吐提升 10.98%**。
可靠的量级结论是本地这组负载约一成改善。之前的 2.916× 和单对 1.321× 不能作为代码净收益，原始记录继续保留。
先前单对训练汇总的 11.65% 也只作为历史观察；当前性能判断以本复测为准。

测量仍有少量调度噪声：按每进程的两场 rollout / 两回合训练分别合计，CPU 时间占墙钟时间最低为 94.73%，一项略低于预设 95% 目标。
**因此不能称为完全独占、零噪声的实验，也不把小数点后的差异解释为精确的因果效应。** 所有 8 次运行均纳入汇总，没有删除慢测量或按结果挑选样本。

## 测量安排

- 共 8 个串行、全新 Python 进程，约 29.5 分钟；每个进程包含两场完整 rollout 和两回合真实训练。
- A 是 pristine `c468663acf05fa11b41eb068169ae44cc79a2376` archive；B 是本轮优化工作树。
- 顺序事先写入 `protocol.json`：B2 AB、B3 BA、B2 BA、B3 AB。每种方法都覆盖两种顺序，减少随时间单向变化的影响。
- 双方由同一外部 loader 加载同一个已封存的 benchmark 文件。没有修改基线文件，没有 `sys.path` 注入。
- i9-12900H，CPU1；仅复测子进程绑定逻辑 CPU 8（Windows CPU 集报告的性能核，物理同核另一线程为 CPU 9）。
  Torch、MKL、OpenMP、OpenBLAS、NumExpr 均限制为 1 线程；固定 `PYTHONHASHSEED=0`。
- seed=2729，原 M20 开发 manifest 中的 `unknown_validation_m20_0001` 与 `_0002`。
  manifest SHA256 为 `9e02e857f16402a249ff84cef5ae16fa8bea3c416521340144bd953b8e8934bc`。
- 每个训练进程仍为 766 环境步、256 次更新；没有改变自然终止、warmup、replay、更新频率或模型初态。
- 每个进程前后执行完全相同的整数/哈希工作负载；原有计时边界额外记录 `process_time()`，没有新增逐步拦截。
- 每 5 秒记录一次电源、绑定核/同核另一线程/整机忙碌率和 Windows 性能计数器，共 350 个样本。
  全部采样保持 AC 供电；电源方案在各进程起止检查中一致。没有更改电源方案、进程优先级或其他应用。

CPU 核类型解释依据 [Microsoft CPU 集结构文档](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-system_cpu_set_information)。
`Processor Frequency` 在本机读出固定标称值；实际运行状态另参考 `% Processor Performance`，不将其当作温度或精确瞬时 GHz 测量。
